# 0.2.0-alpha material runtime breaking change

The 0.2.0-alpha line removes the old control runtime types:

- `MaterialControl`
- `MaterialThemeWatcher`
- `MaterialInteractionHost`
- `MaterialInteraction`
- `MotionGroup`

Material controls now inherit their appropriate Avalonia base class directly. Theme snapshots are
still transported by the inherited `MaterialThemeScope.ResolvedThemeProperty`; internal
`MaterialElementContext` instances own theme publication, interaction state, and the single motion
coordinator for each actual `Control`.

Consumers that previously derived from `MaterialControl` should derive from the relevant Avalonia
base (`TemplatedControl`, `ContentControl`, `Button`, `ToggleButton`, `RangeBase`, or another
component-specific base) and keep component-local token invalidation in `OnPropertyChanged`.
Application code must not construct or cache the internal context, controller, or motion scopes.

This is an intentional source and binary breaking change. There is no compatibility forwarding type.
