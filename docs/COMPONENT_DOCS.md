# 组件文档与维护规约

本文规定两类文档的职责边界、定长骨架与写作禁令。全组件索引见[组件文档](COMPONENTS.md)。

---

## 分工

| 维度 | `README.md` | `INTERNALS.md` |
| --- | --- | --- |
| **主要读者** | 使用者 | 维护者 |
| **核心目的** | 怎么用：变体、XAML 示例、槽位与定制方式 | 怎么改：上游映射、关键机制、已知差异、验证依据 |
| **写作视角** | 业务视角，仅使用公开 API 与 XAML | 引擎内部视角，对照上游源码与框架机制 |
| **绝对禁区** | 尽量不要出现 Compose 内部符号、内部 Controller、Changelog | 严禁写成长篇排查日记、流水账或全量 API 复刻 |

## README.md：使用者指南

严格遵循以下 5 个定长小节，不随意增删层级：

### 骨架模板

```markdown
# <组件名>

简要描述组件用途，以及在 Avalonia 中的实际形态（库内自定义控件，或原生控件配合 Theme / 附加属性）。

## 基础用法

引用命名空间，给出最小可运行的 XAML 片段（不得伪造不存在的 API）：

\`\`\`xml
<m3:<ControlName> ... />
\`\`\`

## 变体与属性

列出常用变体（如 Filled / Tonal / Outlined / Elevated）、尺寸等级、核心属性与命令/事件。

## 内容槽与定制

说明图标槽、主内容槽、模板定制方式与可覆盖样式。

## 使用限制与注意事项

仅记录直接影响使用者的平台约束、布局前提（如需在特定的容器或作用域下使用）及 Catalog 演示入口。
内部移植差异和实现机制请参阅 [INTERNALS.md](INTERNALS.md)。
```

## INTERNALS.md：维护与移植契约

严格收敛为以下 4 个定长小节，保持高信噪比，作为 Agent 和维护者的当前真理来源：

### 骨架模板

```markdown
# <组件名> 内部机制与维护说明

## 1. 上游基线与职责映射

- **上游依据**：Commit ID、上游文件路径及关键符号
- **职责映射**：上游类/Composable 在 Avalonia 侧对应的类、Controller 或附加属性

| 上游符号 / 职责 | 本地类型 / 成员 | 对应说明 |
| --- | --- | --- |
| `Button(...)` | `MaterialButton` | 原生 Button 样式与模板扩展 |

## 2. 关键机制与架构契约

记录容易被改坏的状态机、特殊测量/布局逻辑、动画编排、生命周期与原生模板合约（例如 VisualBrush 局限、PointerCapture 处理等）。

## 3. 已确认决定与已知差异

- **已确认决定**：记录已获维护者确认的非平凡设计。跨组件共享决定直接链接到 [DECISIONS.md](DECISIONS.md)。
- **尚未实现**：属于目标但仍缺失的能力。
- **未经验证**：已实现但仍缺少多端证据的边界。
- **已接受差异**：明确批准的框架特化或与上游不同的行为。

## 4. 验证入口

- **自动化测试**：单元测试 / Headless 测试的项目与测试类路径
- **VisualParity**：对应的视觉一致性用例名称与复现命令
```

## 写作禁令

为防止文档被频繁修改而无限膨胀，以下行为一律禁止：

1. **禁止流水账**：严禁在文档中记录“本次修复了什么 Bug”、“排查过程分析”、“2026-xx-xx 变更记录”。修复完成后，直接就地覆盖/更新当前有效的事实。历史演进由 Git Commit 与 PR 负责。
2. **禁止堆积草稿**：严禁在仓库主树中创建 `*_draft.md`、`*_v2.md` 或临时计划文档。未定稿的思考或临时排查日志只能放在 `artifacts/` 中。
3. **禁止机械罗列清单**：不要在文档中复制全量属性列表或完整的 Token 字典。文档只记录核心关键约定，代码本身即最好的类型定义。
4. **禁止对外泄露内部实现**：对外 `README.md` 中绝不泄露内部 Controller、上游 Kotlin 命名或暂未实现的内部细节。
