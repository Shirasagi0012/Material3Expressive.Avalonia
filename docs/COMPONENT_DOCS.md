# 组件文档约定

组件目录分为两个阅读入口，Button / TextField 先采用这一结构，其余组件按实际维护需要逐步迁移。
文档维护当前事实，不逐轮追加开发日志，也不复制完整 API / Token 清单。

## README.md：使用组件

按读者接入顺序组织，有需要才增加小节：

1. 组件用途与实际入口（原生控件 + Theme、附加属性，或库自身控件）
2. 链接[公共接入](GETTING_STARTED.md)，给出可运行的最小 XAML，声明所用命名空间与宿主前提
3. 常用变体、尺寸、状态、事件/命令，以及绑定所需的 DataContext 假设
4. 内容槽与定制方式，区分原生属性、附加属性和 Token，优先展示 XAML
5. 对使用者有影响的限制、迁移注意事项与 Catalog 入口
6. 链接同目录 INTERNALS.md，不把实现过程放入入门路径

示例必须对应当前源码；完整示例应可编译，片段须说明省略的宿主、绑定对象和事件处理器。
不要为了示例引入尚不存在的 API，也不要承诺未验证的平台行为。

## INTERNALS.md：维护与移植

按修改时需要查证的问题组织：

1. 固定上游基线、文件与关键符号，以及关键本地职责映射
2. 状态转换、布局、动画、生命周期和原生模板合约等容易被改坏的机制
3. 已确认决定的原因、做法、影响、适用范围与确认依据；共享决定链接到 [DECISIONS.md](DECISIONS.md)
4. 明确区分尚未实现、未经验证、已观察到的未解决问题与已接受差异
5. 已跟踪的测试/用例和可复现命令，说明验证范围及证据限制

代码只能证明当前实现，不能独自证明维护者的设计意图或授权。缺少确认依据时保留为问题，
不把暂缓修复或历史遗留写成已接受差异。引用旧文档中有价值的观测时，保留场景与局限；
测试数量和临时机器路径不作长期结论，报告需可由其他维护者访问，否则提供测试来源及复现入口。

## 交叉链接与改动边界

迁移一个组件时，同时核对指向其旧章节的链接；使用入口留在 README，维护说明指向 INTERNALS。
公共接入只维护一份；架构、共享决定、VisualParity 决定仍各归原文档，不因拆分而改名或复制。
仅更改受影响文档，不借文档统一扩大组件重构范围。
