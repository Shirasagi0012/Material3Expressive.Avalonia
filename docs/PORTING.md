# 移植指南

本文规定移植准则；具体执行流程可使用 `$m3e-port-component` Skill。无论是否使用 Skill，以下要求均适用。

## 目标与依据

以固定版本 Compose Material3 为依据，在 Avalonia 中忠实还原组件的逻辑、视觉效果与交互行为。
默认直接翻译能够保留的实现，仅对框架差异进行必要且有依据的适配，使本地代码便于与上游对照和维护。

固定版本与源码入口见 [AGENTS.md](../AGENTS.md#上游源码)。AndroidX 是 Material3 逻辑的默认依据，
涉及桌面平台实现时查看 Compose Multiplatform Core；发现行为差异时明确提出，不自行混用。
读取不到需要的源码时说明缺失范围，不能凭记忆补齐。日常移植不需要通读基线选择与核验记录。

上游源码决定目标行为，样例和测试帮助理解边界。本地实现和历史注释不能证明某项适配已获批准；
已确认的适配与差异按其决定及适用范围执行。

## 范围与理解

实现前明确涉及的组件入口、重载、变体与行为。分阶段暂缺不等于已接受删除。
从入口追踪影响结果的默认值、Token、内部辅助逻辑、布局、内容环境、交互、动画及平台分支，
不能只看主函数或正常状态截图就判定实现完整。

根据组件能力检查状态顺序、取消与中断、禁用状态、内容尺寸、RTL、语义和无障碍等边界，
不适用的内容不必机械展开。同时查阅[架构说明](ARCHITECTURE.md)、实际调用方、组件维护文档（已拆分时为 INTERNALS.md，否则为 README）
中的已确认决定，以及 `docs/DECISIONS.md` 中适用的共享能力决定，识别可复用能力和具体缺口。
涉及 VisualParity 时，从其[阅读入口](../tests/VisualParity/README.md#阅读入口)查阅规则与决定。

通常在任务中简述范围和疑问即可，仅在复杂时列出“上游职责/符号 → 本地位置 → 适配或缺口”，
不要求每次创建计划或映射文档。

## 实现与适配

### 保留上游实现

保留算法、数据关系、分支、状态转换、执行顺序，以及有意义的命名、职责和调用关系。
引用上游时提供基线、文件路径及关键符号，行号只作辅助，不要求逐行标注。
上游有明确共享关系时优先沿用；仅代码外观相似不足以支持建立通用框架，
已有组件的特殊规则也不能未经核对就扩大为共享规则。

语言转换需关注浮点精度、舍入、单位、默认值、运算顺序及更新时机，数学上等价不一定产生相同像素或时序。
保留默认值的计算关系和 Token 的引用关系，不因当前配置下结果相同就改成固定常量或提前展开。

### 选择本地表达

模板、控件组合、内容槽和样式绑定优先使用 XAML。状态流程、动画编排、特殊布局和程序化绘制可以使用 C#，
尽量保留上游的计算与执行结构。表达方式以清晰、可对照和语义一致为依据，
不为使用 XAML 或标准控件改变布局、交互及绘制行为。

框架 API 名称相似不足以证明语义等价。核对布局约束和执行顺序、内容环境的传播与覆盖、输入及生命周期。
例如，继承属性需保留内容环境的更新范围，最小尺寸需保留其在相应布局阶段的作用。

### 复用已有能力

优先消费已有颜色、图标、阴影、动画和 Token 能力，具体入口与限制见架构说明。
动画优先使用 ComposeAnimation 中对应的机制，保留上游的目标选择、规格、编排与中断规则，
生命周期按已确认的作用域方式接入，不仅因声明更短就改成各属性独立动画。

能力不足时指出缺少的上游语义，提出补齐或局部适配方案；不在组件内建立第二套机制，
不静默回退到近似效果。

## 自主执行与设计决定

| 情况 | 处理方式 |
| --- | --- |
| 等价语言转换、已有明确适配 | 核对适用范围后直接实施，不重复请求确认。 |
| 有上游依据、在已授权范围内修正错误 | 直接实施并验证。 |
| 新的非平凡 API、共享抽象或职责调整 | 提出具体方案，由维护者决定。 |
| 行为删减、参数改变、近似效果或其他语义偏离 | 说明上游行为、改变原因及影响，由维护者决定。 |

修正错误仍遵循上述设计边界。普通命名、等价表达和已决定方案内的细节不增加审批步骤。
疑似上游 bug 也应先给出依据，不能在移植时顺手修正。

需要决定的问题应说明上游行为、本地限制与能力缺口、推荐方案及有意义的备选方案、
必要的 C#/XAML 用法和语义影响。完成分析后再请维护者决定；
仅暂停依赖该决定的实现，其他已授权且独立的部分继续。

已确认的选择只在原适用范围内有效。发现代码、文档与上游冲突时指出具体冲突，
不自行挑选最方便的解释，不通过修改规范为实现补授权。

## 验证与交付

根据改动检查源码对应关系和实际运行结果，分别报告源码对照、单元/headless、视觉对比及桌面交互的执行情况。
编译通过不代表对齐上游，模块级验证不代表组件集成验证；
未执行的检查不能写成通过。上游目标升级后，旧验证仍属于旧版本，直到相应范围重新确认。

发现 parity 差异时，修复应有场景、采样或实现方面的原因依据，不能仅凭截图更相似就加入补偿。
修改测试场景、采样或比较方式，需要说明原先哪里不符合验证目标，不能只以失败减少为理由。
修复后重跑相关用例；无法解释差异时继续排查或明确提出未决问题，不靠反复试常量消除差异。

双端用例的覆盖、测量和采样要求见[用例编写](../tests/VisualParity/AUTHORING.md)。
一致性报告只评价提交的事实，未测量的行为不能据此判定已完成，截图一致也不能独自证明交互行为一致。

交付时简要说明实现范围、必要适配、实际验证和剩余问题，区分：

- **尚未实现**：属于目标但仍缺失。
- **未经验证**：已经有实现，但某项一致性仍缺证据。
- **已接受的差异**：维护者明确确认的适配或偏离，附决定及适用范围。

只更新实际受影响的信息，不要求每次移植都产生以下文档：

| 信息 | 位置 |
| --- | --- |
| 通用结构、能力与接入限制 | [ARCHITECTURE.md](ARCHITECTURE.md) |
| 组件使用入口、常用参数与使用边界 | 组件目录的 README，约定见 [COMPONENT_DOCS.md](COMPONENT_DOCS.md) |
| 组件映射、机制、特殊适配、缺口及已确认决定 | 组件目录的 INTERNALS.md；尚未拆分的组件暂存 README |
| 跨组件的共享能力决定 | [DECISIONS.md](DECISIONS.md)，按需记录 |
| VisualParity 的设计决定 | [测试目录的 DECISIONS.md](../tests/VisualParity/DECISIONS.md) |
| 用例覆盖、测量和采样规则 | [AUTHORING.md](../tests/VisualParity/AUTHORING.md) |
| 环境与命令、固定版本与来源 | [README.md](../README.md)及上游基线文件 |

重要决定简述决定、原因、做法与影响、适用范围和确认依据。待讨论方案留在任务中，不追认未经确认的实现。
按约束的代码归属存放，不在根目录复制组件或测试工具的决定；共享职责与组件行为混合时分别记录、按需互引。
决定失效时标明替代关系，改变含义或扩大范围需维护者确认。
普通文档维护当前有效内容，不逐轮追加工作日志，不重复维护源码已清楚表达的完整 Token 表或成员列表。
