# ShortNavigationBar

## Scope

Implement the compact adaptive navigation variant, selection, focus, window-size behavior, and
automation.

## Exit criteria

Breakpoints, state preservation, responsive layout, and documentation are verified.

## Delivered contract

`MaterialShortNavigationBar` is the D012 XAML adaptation of AndroidX ShortNavigationBar. It owns a
direct `Items` collection of existing `MaterialNavigationItem` controls and a two-way
`SelectedIndex`; responsive changes never recreate either. `Arrangement` exposes the upstream
EqualWeight and Centered policies plus Auto. Auto resolves widths below the configurable 600dp
`ResponsiveBreakpoint` to EqualWeight and widths at/above it to Centered, reported through the
read-only `ResolvedArrangement` output.

EqualWeight uses integer physical-pixel division across the complete width. Centered implements
the upstream 20/15/10/5% edge padding for three through six items, intrinsic item growth up to the
equal-share maximum, and final group centering. `MaterialNavigationItem.IconPosition` adds Top and
Start layout: Top uses the 56×32dp indicator and alpha25's 6dp top anchoring, while Start uses a
40dp-high content-width indicator with 16dp horizontal and 8dp vertical padding. Multiline labels
can increase the 80dp minimum bar height.

Desktop arrows wrap through enabled visible items, reverse horizontally in RTL, and update both
focus and selection; Home/End select endpoints and Tab remains ordinary traversal. Automation is
a Tab + ISelectionProvider containing stable real TabItem + ISelectionItemProvider children;
disabled destinations reject provider selection.

## Baseline and parity

Implementation and tests were reviewed against AndroidX `ff0a0a99` / Material3 `1.5.0-alpha25`
`ShortNavigationBar.kt`, `NavigationItem.kt`, `ShortNavigationBarTest.kt`, and
`NavigationBarHorizontalItemTokens.kt` / `NavigationBarVerticalItemTokens.kt` VERSION `v0_11_0`.

The pinned Compose Multiplatform Material3 `1.12.0-alpha03` / Jetpack `1.5.0-alpha22` desktop
producer exposes the API but cannot provide valid layout evidence. The diagnostic artifact
`artifacts/visual-parity/xunit/20260730-180515-872` measured each of three items at the complete
bar width: the 360dp EqualWeight probe produced three 360dp items rather than three 120dp items,
and the 600dp Centered probe likewise produced three 600dp items. This disagrees with alpha25's
container measure policies and upstream device tests. Both diagnostic cases were removed from the
formal registry, no tolerance was changed, and ShortNavigationBar static parity is explicitly
**unavailable for the pinned reference**. Alpha25 geometry is covered by deterministic Avalonia
layout tests instead.
