# SharedElement / SharedBounds 内容语义试验

本文记录第四阶段的内容选择原型。正式 `SharedTransitionHost`、`SharedElement` /
`SharedBounds` API 和协调器已在后续阶段落地；下文固定 Viewbox 与 Scratchpad 描述保留为
历史验证背景，当前使用方式见 [SharedElement / SharedBounds](SHARED_TRANSITION.md)。

## 绘制契约

| 模式 | 运动中的父层 | 独立图片层 | 完成后 |
| --- | --- | --- | --- |
| SharedElement | 只捕获目标 Root，按动画矩形绘制 | 只捕获目标 ImageRoot | 目标原树接管 |
| SharedBounds | 源 Root 淡出，目标 Root 淡入，共用动画矩形 | 源图片淡出，目标图片淡入 | 目标原树接管 |

`SharedContentOverlay` 管理两组画刷，画刷仍通过 Visual 置空再恢复显式失效。
SharedElement 完全不创建源端画刷；源端的退出保留是生命周期所有权，不表示源端也参与绘制。
初始运动矩形来自源端，但其中的内容从共享过渡开始就是目标内容。

SharedBounds 的淡变值由退出 Scope 上的真实 Runtime 动画产生，0 表示源层全显、1 表示目标层全显。
源层先画，目标层后画，透明度分别为 `1 - fade` 和 `fade`。这是独立透明度的 source-over 合成：
中间帧允许背景透出，不是线性色彩插值或固定不透明的图像混合。淡变与边界、图片弧线分别计时，所有动画完成才释放退出内容。

原型中的两种模式都使用 `Stretch.Fill` 缩放已布局内容。正式 `SharedBounds` 后来增加了
`ScaleToBounds` / `RemeasureToBounds`：后者在自动局部或显式 lookahead 域中逐帧重排真实内容，
并以 `Stretch.None` 搬运已重排的 capture。两个端点可以来自不同域，各自保有快照并转换到
共同 SharedHost 坐标系。原型的固定大小 Viewbox 内容只验证早期缩放模式。

开启独立图片时，两端父记录都排除自己的图片 Gate，图片子层在父层之后绘制，并继承动画卡片圆角裁剪。
关闭去重或裁剪的选项仍保留为阳性对照。

## 失败和清理

准备超时或源端提前卸载只代表无法执行共享过渡，不应使已请求的目标变成永久空白。
试验使用以下明确策略：

- 目标槽仍在宿主中且目标可见：清除 overlay，恢复目标 Gate；源 Gate 保持隐藏，释放 reservation 和真实动画。
- 目标在运动中离树：恢复源端的 Visible 和 Gate，隐藏目标，释放动画及 reservation。试验随后把移除的测试槽以隐藏状态装回，允许再次尝试。
- 重置：递增 generation 后先清理会话，再重建初始页面；过期帧回调不改变新状态。

会话先标记结束，再释放资源，避免 Scope 清理回调重入。源/目标的图片 Gate 都恢复，以免在取消后留下内容空洞。
正常完成依旧只交还目标绘制，交接当帧及后两帧检查旧端没有重新显现。

该回退是试验 App 的页面策略。正式库应恢复绘制所有权并报告失败，由导航层决定继续目标或回退；
不应让通用共享元素控件擅自修改应用导航状态。两端同时离树、跨根迁移、外部业务取消等需要正式会话协调器处理。

## 验证方式

`ContentPixelChecks` 在真实桌面后端使用 RenderTargetBitmap 读取像素：源蓝、目标红，验证 Element 在起点、
中点、终点始终使用目标；目标改绿后下一次显式刷新读取绿；Bounds 验证源、混合、目标三个样本。
另验证独立图片的内容选择和清理后的透明像素，分别运行显式失效与重建画刷两种策略。

这些离屏像素检查覆盖内容身份与合成，不代替桌面合成时间序列、文字重排、闪烁、任意嵌套的人工验收。
生命周期 smoke 覆盖两种模式的往返、嵌套布局、超时、目标离树、零时长及失败后不重置继续返回。
Runtime 回归另验证边界先结束时淡变继续保留退出内容。

后续已完成 [进程 CPU / 托管分配 / 合成批次测量](SHARED_REFRESH_PERFORMANCE.md)，GPU 执行和上屏时间仍未覆盖。
自动 key 匹配和通用协调器已在后续正式实现中完成；交互式 seeking 尚未实现。
