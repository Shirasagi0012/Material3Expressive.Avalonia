# SharedTransition 后续实施计划

制定日期：2026-09-09。当前基线：355 项测试通过；正式库已有准备事务、Session、双端保留、自动匹配、布局重定向与 generation / layout revision 校验。
尚未完成真实绘制 Host、公开端点控件、默认布局读取器和绘制后端。本文是实施计划，未将下面的接口名称视为已经发布的 API。

目标是交付同一 Host 内可直接使用的 SharedElement / SharedBounds：正常往返、运动中反向、目标布局变化、动态内容刷新、失败回退及嵌套共享元素。
动画继续使用调用方的共同父 Transition；显式 BeginUpdate 仍是可选入口。

## 1. 确立目标布局和绘制交还契约

先在现有 SharedTransitionProbe 补齐两组小规模试验，保留现有正反对照与测量方式。

- 布局：同一端点分别放入 Canvas、Grid、StackPanel、ScrollViewer，覆盖 None、slide、scale、expand、RTL 和不同 DPI。
  区分源端当前显示边界、目标端最终布局边界、动画绘制矩形。只剥离库自身的展示效果，不能误删用户的静态变换。
  尤其检查 expand 引发的父布局和兄弟位置变化：这不是简单求逆 RenderTransform 能解决的问题。
- 绘制：验证末帧 overlay、目标原树恢复、源绘制继续抑制和端点保留释放的先后顺序。
  使用真实桌面后端的连续采样，检查首帧、结束帧及后续帧；涵盖零时长、同帧反向、结束时目标离树。

产出：坐标契约、支持矩阵和 Host 的交还时序。明确遇到不可逆变换、跨 TopLevel、无法取得最终布局时的回退。
若一般 expand 场景需要额外目标布局机制，单列实现依赖；最小 Host 可先在明确支持的布局场景下交付，不能把当前动画位置冒充最终位置。
Processed / Rendered 只用于验证相应合成阶段，不能当作实际显示或 GPU fence 的证明。

验收：固定的目标布局不随共享动画采样漂移；动态目标改变可定位到新终点；交还过程中未观察到重复绘制、源端回闪或空白间隙，并说明采样覆盖范围。

## 2. 实现内部 Host 和端点基础设施

先形成内部可运行结构，再固定公开属性。

- Host 建立内容层与独立 overlay 层，统一布局坐标、协调器、布局通知和准备截止策略。
- 每个端点分成外层绘制抑制层与内层内容捕获层。共享过程保持内容的逻辑父级、DataContext、绑定和用户设置的 Opacity / RenderTransform。
- 随最近 AnimatedVisibilityScope 创建、替换、销毁而注册或注销；明确最近 SharedTransitionHost 的作用域边界，禁止跨 Host 配对。
- 完整布局后合并通知 LayoutCompleted；避免布局回调递归、逐端点重复扫描和按动画矩形重新布局内容。
- 为准备等待提供可取消、可测试的截止策略；没有布局通知也必须能释放准备。截止回调携带 generation，时长策略集中配置。
- 定义输入行为：overlay 不接收命中；抑制端点绘制时也处理其命中状态，避免在原位置留下不可见点击区；不克隆可交互内容。
- 分清 Session 和退出端绘制抑制的寿命：共享先结束而普通退出动画仍运行时，源端不能因清理 Session 再次显现。反向、注销和新匹配必须正确转交这份抑制所有权。

验收：真实控件模板迟到、Content / Key / Scope 替换、离树再挂载、Host 替换、无匹配和超时均释放资源；共同父级仍只有调用方的动画循环。

## 3. 完成 SharedElement 的可见端到端路径

- 实现 ISharedTransitionBackend / ISharedTransitionPresentation，以目标端内层 Visual 创建 VisualBrush；源端仅提供起点与生命周期保留。
- 复用画刷并显式失效，先采用已经验证正确的刷新路径；绘制首帧使用 Pair.SourceBounds，后续读取真实 Runtime Bounds 动画。
- 只缩放已经布局的目标内容，目标布局不依赖运动中的绘制矩形。
- 按阶段 1 的时序恢复目标原树、移除 overlay 并释放 Session。所有交还通过 motion.TryComplete，校验 generation 与 LayoutRevision。
- 同一对端点反向时更换内容来源和角色，继续使用已有 bounds 动画。取消只恢复绘制所有权，不修改业务导航状态。

验收：源蓝目标红的内容身份像素测试、运行中目标更新、正反向轨迹、零时长和结束后源不回闪；示例不再需要用户手工注册、提供 Rect 或操纵绘制抑制层。

## 4. 扩展 SharedBounds 并确定公开 API

- 源和目标各自捕获，在同一个动画矩形中分别淡出 / 淡入；内容动画注册在 Session 时间轴上。
- 内容淡变和 bounds 可以使用不同 spec；Session 等待全部真实动画完成。
- 反向时按稳定端点身份更新各自透明度，验证当前可见结果的连续性，不能只交换 brush 后把 fade 重新设为 0。
- 公开 API 候选为 SharedTransitionHost、SharedElement、SharedBounds；共同配置包括 Scope、Key 和 BoundsTransform，具体命名在端到端实现验证后确定。
- 明确未匹配时沿用普通显示、模式不兼容时回退，以及跨 Host、重复 Key 等诊断的展示方式。
- 补齐 XAML、Style、模板和代码创建方式，并编写列表到详情的正式示例。

验收：源 / 中间合成 / 目标像素正确，bounds 先结束而淡变未结束时继续保留；反向不重置可见透明度；准备失败后无需重置页面即可再次导航。

## 5. 推广嵌套、裁剪与坐标支持

- 从原型固定的一张卡片加图片推广到动态端点树。父捕获排除由独立 Session 绘制的子内容，子绘制继承约定的父裁剪。
- 定义嵌套层级、圆角裁剪、多个兄弟的绘制顺序，以及父子 Session 不同时完成时的交还规则。
- 嵌套子元素没有成功配对或中途退出时，父内容应恢复完整绘制，避免图片空洞。
- 按阶段 1 的支持矩阵补齐普通用户变换、滚动、RTL、DPI 和进入/退出效果组合；需要目标布局机制的场景在此完成或维持明确回退。

验收：任意注册顺序下的父子去重与裁剪、不同结束时间、子元素取消、滚动和窗口缩放；通过桌面像素与时序检查。

## 6. 完整路径性能测量与交付

- 将既有性能场景接到正式 Host，覆盖 1 / 4 / 16 对、静态和动态内容、两种模式及嵌套。
- 将匹配、布局读取、Runtime 动画、内容刷新、录制和合成纳入测量，复用普通控件基线与原型数据作对照。
- 记录 CPU、托管分配和合成批次延迟；按实际瓶颈决定是否增加内容脏标记或保留录制结果。尚无可靠子树变化通知时，保留保证动态正确性的刷新路径。
- 检查长时间往返及取消后是否累积 Session、画刷、事件订阅、定时器或端点引用。
- 更新使用文档、支持矩阵、诊断说明及演示；运行全库回归、桌面内容像素测试、生命周期 smoke，并进行人工视觉验收。

验收：可复制运行正式 API 示例；行为测试和清理检查通过；性能数据包含环境、方法和误差边界，未测 GPU / 上屏项目明确标记。

## 执行顺序与范围

依次推进 1 → 2 → 3 → 4 → 5 → 6。阶段 3 是第一个可见交付点，阶段 4 完成两种内容语义，阶段 5 扩展复杂布局与嵌套支持。
每阶段先满足自己的验收条件，再扩展下一层；不同时改变匹配、坐标和内容语义，以便失败时定位原因。

本轮计划暂不纳入跨窗口共享、交互式 seeking、三端 A → B → C 连续接力、每帧重测量的 ResizeMode 和任意可视内容的无损捕获保证。
其中第三端点当前可走新 Session / 回退，但不能宣称已经实现速度连续接力。
