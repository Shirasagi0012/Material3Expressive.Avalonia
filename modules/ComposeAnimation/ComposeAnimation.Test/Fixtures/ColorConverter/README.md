# Fixed Compose ColorConverter values

`compose-reference.jsonl` is generated by the actual `Color.VectorConverter(ColorSpaces.Srgb)`
in Compose Multiplatform `1.13.0-alpha01`, source commit
`a9e47e8aa04c95cfe572ab4297c770f3cbfb234e`. AndroidX fixed commit
`f3ed195f0c9ef9eafe437351d974c9ec49ecc2ea` has identical converter and graphics source files.
The generator does not duplicate the color algorithm or take outputs from C#.

The values cover a byte-RGB grid, every input alpha, deterministic arbitrary colors and vectors,
gamut clipping, Half halfway/subnormal boundaries and 10-bit alpha rounding boundaries.
216 spring samples use upstream TargetBasedAnimation for forward, reverse, chromatic and alpha
animations with critical, under- and over-damped specifications at integer millisecond times.
Vectors are serialized JVM Float values and read back as Float before widening to double.
The `output` of a `to` record is upstream From(To(color)); it need not equal its original ARGB.
Animation endpoints are original Color values, as in upstream TargetBasedAnimation.

From the Material3ExpressiveRefactor root with the locked reference already built:

```powershell
$fixture = '../ComposeAnimation/ComposeAnimation.Test/Fixtures/ColorConverter'
$jars = (Resolve-Path 'tests/VisualParity/reference/build/install/Material3ParityReference/lib').Path + '/*'
$output = (Resolve-Path 'artifacts/color-converter-0.2.1-alpha').Path
& 'C:/Program Files/Java/jdk-25/bin/javac.exe' -cp $jars -d $output "$fixture/GenerateComposeReference.java"
& 'C:/Program Files/Java/jdk-25/bin/java.exe' -cp "$output;$jars" GenerateComposeReference |
    Set-Content -LiteralPath "$fixture/compose-reference.jsonl" -Encoding utf8
```

Dependencies are the existing locked producer jars, not a floating source checkout or version.
